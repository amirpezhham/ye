# راه‌اندازی backend محلی

این مرحله یک API مستقل Node.js/Express با PostgreSQL، نشست امن پنل و صف اعلان تلگرام فراهم می‌کند. فرانت‌اند اکنون کاملاً به این API متصل است (فروشگاه، پنل ادمین و سفارش‌ها) و دیگر از `localStorage` برای داده‌های اصلی استفاده نمی‌کند؛ `localStorage` فقط به‌عنوان منبع انتقال یک‌بارهٔ داده‌های قدیمی باقی مانده است. برای انتشار روی هاست به `docs/deployment.md` مراجعه کنید.

## پیش‌نیازها

- Node.js نسخه 22 یا بالاتر
- PostgreSQL نسخه 14 یا بالاتر
- ساخت یک پایگاه‌داده و کاربر PostgreSQL مختص برنامه

## اجرای محلی

1. `npm install`
2. کپی `.env.example` به `.env` و تنظیم `DATABASE_URL` و یک `SESSION_SECRET` تصادفی با حداقل ۳۲ کاراکتر.
3. اجرای `npm run db:migrate`
4. ساخت حساب مدیر با `ADMIN_USERNAME` و `ADMIN_PASSWORD` (حداقل ۱۲ کاراکتر) داخل محیط اجرا، سپس `npm run db:create-admin`.
5. اجرای API با `npm run api:dev`.
6. بررسی سلامت از `GET http://localhost:4000/api/health`.

برای ارسال اعلان سفارش، علاوه بر تنظیمات پایگاه‌داده، `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` را فقط در `.env` سرور قرار دهید. این مقادیر نباید در Vite، مرورگر یا فایل‌های `VITE_*` قرار گیرند.

## APIهای پیاده‌سازی‌شده

- عمومی: محصولات، دسته‌بندی‌ها، مطالب، تنظیمات، ثبت سفارش و سلامت سرویس
- مدیر: ورود/خروج با کوکی `HttpOnly`، تغییر رمز، مدیریت محصولات/دسته‌بندی/مطالب/تنظیمات، سفارش‌ها و فهرست مشتری‌ها
- ثبت سفارش قیمت را از پایگاه‌داده محاسبه می‌کند، موجودی قابل‌ردیابی را در تراکنش رزرو می‌کند و اعلان تلگرام را از صف retryable می‌فرستد.
- بعد از ورود مدیر، از «تنظیمات پنل» می‌توان داده‌های `localStorage` همان مرورگر را یک‌بار منتقل کرد. این انتقال در کل پایگاه‌داده فقط یک بار مجاز است؛ پیش از اجرا مرورگر دارای نسخهٔ کامل داده‌ها را انتخاب کنید.

## محدودیت‌های این مرحله

- داده‌های محصولات/دسته‌بندی/مطالب باید یک‌بار از مرورگر منتقل یا درج شوند، وگرنه فروشگاه خالی نمایش داده می‌شود (بخش «انتقال داده» در `docs/local-dev-runbook.md`).
- انتقال داده‌های فعلی مرورگر، آپلود فایل به فضای ذخیره‌سازی پایدار، بازیابی رمز و آزمون یکپارچه با PostgreSQL باید پیش از launch انجام شوند.
- HTTPS، `ADMIN_ORIGIN`، گواهی/تنظیمات TLS پایگاه‌داده، پشتیبان‌گیری و سیاست‌های نگهداری اطلاعات مشتری باید در محیط استقرار نهایی تنظیم شوند.
- هیچ حساب مدیر یا رمز پیش‌فرضی در backend ساخته نمی‌شود؛ حساب اولیه فقط با فرمان مدیریت‌شده ساخته می‌شود.
